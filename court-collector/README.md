# 법원경매 수집기 (전용 PC용)

정비경매 리포트(jbslab.co.kr/auction)에 법원경매 물건을 넣는 프로그램입니다. **평소 안 쓰는 컴퓨터 한 대(미니PC)** 에서만 돌립니다.

## 원칙
- 최대한 천천히: 5시간 돌고 3시간 쉼(01~06, 09~14, 17~22시). 하루 1,000화면을 그 시간에 고르게 펴서 화면마다 1분 안팎 쉬고, 30화면마다 4~10분 쉼. 1,000화면을 채우면 그날은 끝.
- 수도권 16개 법원의 진행 물건만. 처음 한 번 전체, 그 뒤로는 바뀐 물건만 상세를 다시 엽니다.
- **차단·보안문자가 나오면 우회하지 않고 멈춥니다.** (`state/blocked.txt` 가 생기면 다음 날도 쉼 → 확인 후 지우면 재개)
- 개인정보·키 파일(.env)과 수집 기록(state, logs)은 저장소에 올리지 않습니다.

## 설치 (미니PC에서 한 번)
1. Node.js 20 이상, Git 설치
2. 저장소 받기: `git clone https://github.com/deepgreen7857-creator/redev-feasibility C:\jbslab`
3. ```bat
   cd C:\jbslab\court-collector
   npm install
   npm run setup-browser
   copy .env.example .env
   ```
4. `.env` 의 `INGEST_TOKEN` 에 서버에 넣은 것과 같은 토큰을 적습니다(아래 「토큰 만들기」).

## 화면 읽기 완성 (처음 한 번, Claude Code가 함)
`src/site.js` 의 TODO 3곳(`listCourt`, `readDetail`, `backToList`)을 실제 법원경매정보 화면을 보면서 채웁니다.
그다음 시험: `npm run test-run` → 3건만 읽고 서버에 올리지 않고 결과를 보여 줍니다.

## 첨부 원본 받기 (상세 읽기 판 4)
상세를 읽는 물건마다 **매각물건명세서·감정평가서·현황조사서 PDF와 상세 화면 사진**을 받습니다(버튼을 눌러 문서를 보는 것과 같은 요청, 화면 수 한도에 넣어 셈).
- 원본은 이 PC 하드에 그대로: 등기부와 같은 `D:\법원경매원본\<법원>\<연도>\<사건번호>\<물건번호>\` (매일 새벽 E:로 백업). 병합·중복사건이 함께 쓰는 문서는 `D:\법원경매원본\_공유문서\` 에 한 번만.
- 사이트에는 PDF의 **글자·쪽은 그대로 두고 안의 사진만 화면용(긴 쪽 1600픽셀)으로 줄인 것**을 올립니다(src/slim.js). 줄인 뒤 쪽 수·글자가 원본과 다르면 원본을 올립니다. 22MB 넘는 것은 하드에만 두고 "원본 보관 중" 표시. 상세 화면 사진은 긴 쪽 1000픽셀로 줄여 올립니다.
- 현황조사서는 팝업이 글자 화면이라 원문 글자를 그대로 저장합니다(OCR 없음). 팝업 안 사진도 함께 받습니다. 글자는 점유자 이름 등이 있어 관리자 전용입니다.
- **PDF 열기 버튼은 관리자 로그인에서만 보입니다.** 파일 주소는 관리자만 읽는 모음(`courtFiles`)에만 있습니다. 사진은 누구나 봅니다.
- 못 올린 첨부는 `state/files-pending.json` 에 남아 다음 회차 처음에 다시 보냅니다.
- 판이 4로 올라가서 이미 읽은 물건도 차례로 다시 열어 첨부를 받습니다(하루 1,000화면 안에서 천천히).

## 매일 자동 실행 (돌 때마다 저장소 최신판을 스스로 받음 — start.cmd)
```powershell
powershell -ExecutionPolicy Bypass -File .\install-task.ps1
```
멈추려면 `config.json` 의 `"enabled": false` 또는 작업 스케줄러에서 삭제.

- **서버 전송 실패:** 504·끊김이면 30초·1분·2분 뒤 다시 보냅니다. 그래도 안 되면 그 묶음은 들고 있다가 다음 묶음과 함께 보내고 수집은 계속합니다. 묶음 세 개가 연달아 실패하면 그 회차만 멈추고(`stoppedBy: "upload"`), 못 보낸 물건은 다음 회차에 상세를 다시 읽습니다. 토큰 오류(401)는 바로 멈춥니다.
- **두 개 동시 실행 방지:** `state/run.lock` 에 돌고 있는 수집기 번호를 적어 둡니다. 작업을 멈췄는데 node 가 남아 있으면 새로 켠 쪽은 "이미 다른 수집기가 돌고 있어" 로그만 남기고 끝납니다. 새 코드로 바로 바꾸려면 남은 node 를 먼저 끕니다.

## 토큰 만들기 (노트북에서, 서버 쪽)
```bat
cd C:\notedata\auction-server
firebase functions:secrets:set COURT_INGEST_TOKEN
firebase deploy --only functions
```
토큰은 아무 긴 문자열이면 됩니다(예: 비밀번호 생성기로 40자). 같은 값을 미니PC `.env` 에 넣습니다.

## 등기부 열람본 자동 자료화 (마이옥션, 관리자 전용)
지금 경매 중인 법원 물건 중 열람본이 아직 없는 것을 입찰일 가까운 순으로, 마이옥션에서 사건번호로 찾아 물건마다 붙은 등기부(건물·토지·집합건물) 열람본 PDF를 받습니다.
- PDF 원본은 `D:\법원경매원본\법원\연도\사건번호\물건번호\등기부_종류_마이옥션열람_열람일.pdf` 에 둡니다(매일 새벽 E:로 백업, 그 폴더가 없는 PC는 `state/registry`). 그리고, 정리한 갑구·을구·'주요 등기사항 요약'만 서버의 관리자 전용 모음(`registry`)으로 보냅니다. 주민·법인 등록번호는 지웁니다.
- 물건에는 이름 없는 표시만 붙습니다(`registryFlags`: 말소기준권리 후보, 그보다 앞선 가처분·가등기·전세권·지상권 등, 가압류·압류·근저당 합계, 공유 여부). 관리자 화면 물건 상세의 '등기부(열람본)' 카드에서 봅니다.
- 천천히: 물건 사이 50~120초, 15건마다 5~15분 쉼, 08~23시, 하루 120건. 마이옥션에서 못 찾거나 열람본이 없는 물건은 7일 뒤 다시 봅니다.

처음 한 번 (미니PC):
```powershell
cd C:\jbslab\court-collector
npm run myauction-login          # 뜬 창에서 마이옥션 로그인 → 로그인되면 저장하고 창이 저절로 닫힘(state/myauction-cookies.json)
npm run registry-test            # 2건만 받아 정리 결과를 state/registry-test.json 에 (서버에 안 보냄)
powershell -ExecutionPolicy Bypass -File .\install-registry-task.ps1   # 매일 자동
```
로그가 `로그인 필요` 로 끝나면 `npm run myauction-login` 만 다시 하면 됩니다. 로그: `logs\registry-날짜.log`
