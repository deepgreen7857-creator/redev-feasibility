# 지시문: /urban 경계 도로 확폭 추천 수정 (부분 확폭·면적 채우기 확폭 금지)

작성: 채팅 Claude (2026-11-01) / 대상: 노트북 Claude Code / 저장소 C:\notedata

## 문제 (숭의2구역에서 발견)
- 정비기반시설 탭 좌측 하단 492-34 도로(구역 모서리에 짧게 닿음)를 그 짧은 구간만 25m로 넓히라는 추천이 나옴.
- 결과가 도로 중간에 짧게 튀어나온 병목 모양 → 교통 기능 없음, 도시계획도로 결정으로도 성립 안 함.

## 원인
1. `urban/urban.js`의 `fillSuggest(inf, need)` — 확보 목표 **면적 부족분을 채우려고** 경계 도로를 한 등급씩 넓힘. 확폭은 기능으로 정하는 것이지 면적 채우기 수단이 아님.
2. 확폭 대상 필터가 `front >= 10`(구역에 닿은 길이 10m 이상)뿐이라, 모서리만 스치거나 블록 면 일부만 닿는 도로도 대상이 됨.

## 고칠 것

### 1. 부족분 채우기에서 도로 확폭 제외
- `fillSuggest`는 도로 확폭 단계를 만들지 않는다.
- 부족분은 다음 순서로 안내만 한다(자동 적용 버튼은 공원 쪽만 유지하거나 없앰):
  1) 공원·녹지 면적 늘리기(법정·제안 기준 이상)
  2) 공공공지
  3) 구역 안 도로(✂ 구역 안 도로 남기기/신설)
- 안내 문구 예: "확보 목표가 ○○㎡ 모자랍니다. 도로 확폭은 기능(진입도로 기준·도시계획도로 결정·교통성 검토)으로만 정하므로 부족분 채우기에는 쓰지 않습니다. 공원·공공공지·구역 안 도로로 채우세요."
- 기존 `fillApply`(추천대로 적용)는 도로 폭을 넣지 않도록 바꾸거나 제거.

### 2. 확폭은 기능상 필요한 경우만 추천
`entrySection`의 도로별 `p.rec`(추천 폭)는 아래 중 큰 값만 쓴다. 그 외 이유로 등급을 올리지 않는다.
- 진입도로: 주택건설기준 등에 관한 규정 제25조 폭(1개/2개 기준)
- 도시계획도로로 결정된 도로: 결정 등급의 하한 폭
- 일방통행·최소 폭 기준(지금 쓰는 값 유지)
- (나중) 교통성 검토 결과 `site.constraints.traffic.확폭_검토_도로`가 있으면 그 폭

### 3. 부분 확폭(병목) 걸러내기
- 도로마다 "구역에 닿은 연속 길이"와 "그 도로의 블록 면 길이(구역 경계를 따라 그 도로와 맞닿은 구간 양끝이 교차로/도로 끝에 닿는지)"를 계산한다. 정확한 블록 길이가 어렵다면 개략으로:
  - 닿은 길이 < 30m 이거나
  - 닿은 길이가 그 도로 필지 길이(필지 긴 변)의 50% 미만
  → `partial = true`
- `partial` 도로는
  - 자동 추천(`auto`)에서 확폭하지 않음(현황 유지로 추천)
  - 사용자가 직접 넓은 폭을 고르면 표의 "추천 근거" 칸에 경고: `<b class="warn">부분 확폭(병목) — 구역에 닿은 구간 약 ○○m뿐이라 연속 확폭이 아님. 도로 전체 확폭은 도시계획도로 결정으로 따로 검토</b>`
  - 진입도로로 고를 때 이미 있는 "모퉁이만 닿음" 경고(<10m)는 그대로 두고, 30m 미만이면 "짧게 닿음" 경고 추가
- 지도에서 `partial` 도로의 확폭 표시(진회색 면)는 그리지 않거나, 빗금+점선으로 '검토용'임을 구분.

### 4. 확인
- 숭의2구역 A안: 492-34는 추천이 "현황 유지"가 되고, 부족분 안내에 도로 확폭이 나오지 않아야 함.
- 진입도로 500(20.5m)은 그대로 진입도로 기준 판정.
- 다른 안(B·C)에서도 콘솔 오류 없는지, 정비기반시설 합계 면적이 확폭 제외만큼 줄었는지 확인.
- `node --check urban/urban.js`, `urban/index.html`의 `urban.js?v=` 번호 올리기.
- CLAUDE.md /urban 항목에 한 줄: "경계 도로 확폭은 기능(진입도로·도시계획도로 결정·교통성 검토)으로만 추천. 면적 부족분 채우기에 쓰지 않음. 짧게 닿은 도로는 부분 확폭 경고."
