# jbslab.co.kr/urban — 정비구역 지정 및 정비계획 초안 사이트

> 저장소: `redev-feasibility` (노트북 `C:\notedata`) / 배포: GitHub Pages / 경로: `jbslab.co.kr/urban`
> 이 문서 1부는 기획(사람이 읽는 부분), 2부는 노트북 Claude Code에 그대로 붙여 넣는 지시문입니다.

## 1부. 기획

### 1. 목적

구역계를 그리면 아래 결과가 한 번에 나오게 합니다.

1. **입안대상지역 요건 판정**: 시행령 별표 1과 인천 조례 기준 충족 여부, 미달 항목과 부족분
2. **정비계획 초안**: 법 제9조 각 호 항목을 채운 초안 도서와 표
3. **체크리스트**: 입안 요청부터 지정·고시까지의 절차와 누락 항목

jbslab 본체와 마찬가지로 두 모드를 둡니다.

- **설정 모드**(추진 주체): 구역계 입력 → 요건 판정 → 계획 초안 자동 작성
- **검토 모드**(담당 공무원): 제출된 정비계획(안)의 수치를 공부·법정 기준과 대조 → "이러이러한 오류가 있음" 목록 출력

### 2. 법령 근거(구현 시 기준이 되는 조문)

| 구분 | 조문 | 사이트에서 쓰는 곳 |
|---|---|---|
| 정비구역 지정 | 도시정비법 제8조 | 지정권자·입안권자 구분 |
| 정비계획의 내용 | 법 제9조 제1항 각 호, 시행령 제8조 | 초안 도서 목차(아래 4장) |
| 생활권 세부계획 | 법 제9조 제3항 | 기본계획 생활권 연계(선택 기능) |
| 작성기준 | 법 제9조 제4항(국토부 고시) | 도서 서식·작성방법 |
| 입안대상지역 | 시행령 제7조 제1항 및 **별표 1**(2025.7.29. 개정) | 요건 판정 엔진 |
| 노후·불량건축물 | 법 제2조 제3호, 시행령 제2조, 인천 조례 | 노후도 산정 |
| 재건축진단 | 법 제12조 | 재건축 유형일 때 체크리스트 |

| 주민의견청취 | 법 제15조(서면통보·주민설명회·30일 이상 공람·지방의회 의견) | 절차 체크리스트 |
| 결정·지정고시 | 법 제16조 | 절차 체크리스트 |
| 용적률 완화·국민주택규모 | 법 제54조, 제66조 | 밀도계획 계산 |
| 경미한 변경 | 시행령 제13조 | 검토 모드 변경 판정 |

**별표 1 재개발 요건 구조(현행)**
- 노후·불량건축물 **수** 60% 이상(재촉지구 50%, 그 외는 시·도조례로 50~70% 범위 조정 가능), **그리고**
- 다음 중 하나: 가) 기반시설 정비로 과소토지화 우려, 나) 노후·불량건축물 **연면적** 60% 이상 또는 건축물 과밀, 다) 인구·산업 과도 집중
- 국토부령으로 정하는 무허가건축물을 노후도 분자·분모에 포함(2025 개정 반영)
- 제5호: 부지 정형화 등을 위해 도시계획위원회 심의를 거쳐 입안대상지역 면적의 **120% 이하**까지 확대 가능(시·도조례 범위)

**인천 쪽 반영 사항**
- 「2030 인천 도시·주거환경정비기본계획」 변경 고시(2026.4.27.): 3종 일반주거 상한용적률 상향, 현황용적률 인정 특례 신설, 공공기여 기준 완화, 구청장 직접 입안 시 주민 동의요건 완화
- 인천 조례의 세부 수치(노후도 증감, 과소필지·접도율·호수밀도 기준, 면적 하한, 기준/허용/상한용적률, 공공기여율)는 **설정 파일(`rules/incheon.json`)의 값**으로 분리합니다. 값은 조례 원문과 대조해 채운 `incheon.json`을 함께 드립니다(2026.10.30. 대조). 각 값에 `status`를 붙였습니다. `verified`는 원문 대조를 마친 값이고, `press`는 기본계획 고시문 원문 없이 보도로 확인한 값입니다. 코드에 숫자를 박아 넣지 않게 합니다.

### 3. 입력 데이터

| 데이터 | 출처 | 비고 |
|---|---|---|
| 연속지적도(필지 경계·지번·지목·면적) | V-World API(개인 키) | 구역계와 교차해 편입 필지 추출 |
| 토지이용계획(용도지역·지구) | V-World 토지이용계획 API | 혼재 시 면적 비율 |
| 토지특성(공시지가·형상·도로접면) | V-World / 공공데이터포털 | 과소필지·접도 판정 보조 |
| 건축물대장(표제부: 사용승인일·구조·층수·연면적·용도) | 공공데이터포털 건축HUB 건축물대장 API | 노후도 산정의 핵심 |
| 도로 폭 | 연속지적의 지목 '도' + 수동 보정 | 주택접도율(폭 ○m 이상) |
| 무허가건축물 | **수동 입력** | 공부에 없음 — 별도 표로 입력 |
| 소유자 수·동의서 | **수동 입력(브라우저 내에서만 처리)** | 개인정보 — 서버·저장소 저장 금지 |

### 4. 정비계획 초안 도서 목차(법 제9조 제1항 기준 자동 생성)

1. 정비사업의 명칭
2. 정비구역 및 그 면적 (구역계 경위서, 편입 필지 조서)
3. 도시·군계획시설의 설치에 관한 계획
4. 공동이용시설 설치계획
5. 건축물의 주용도·건폐율·용적률·높이에 관한 계획 (밀도계획 계산표)
6. 환경보전 및 재난방지에 관한 계획
7. 정비구역 주변의 교육환경 보호에 관한 계획
8. 세입자 주거대책
9. 정비사업시행 예정시기
10. 공공지원민간임대주택 등 관련 사항(해당 시)
11. 시행령 제8조의 사항(정비사업 방식, 토지이용계획, 기반시설 설치계획, 교통계획, 현황 조사 결과 등)

부록: 현황분석(노후도·과소필지·접도율·호수밀도 표와 지도), 입안대상지역 판정표, 절차 체크리스트

### 5. 화면 구성

**기준 디자인(시제품)**: `urban-prototype.html` (2026.10.30. 제작, 예시 구역 데이터로 동작). 화면 배치, 단계 탭, 도면 표기(구역계 적색 일점쇄선), 계산 로직(노후 판정·호수밀도·접도율·요건판정·토지이용·밀도·세대수·비례율)을 이 파일 그대로 따릅니다. 실제 구현에서는 예시 데이터 생성부만 V-World·건축물대장 수집으로 바꿉니다.


```
/urban
 ├─ 1. 구역계        지도에서 폴리곤 그리기 / SHP·GeoJSON 불러오기 / 기존 구역계 A·B안 비교
 ├─ 2. 현황분석      편입 필지·건축물 자동 집계 → 노후도(동수·연면적), 과소필지, 접도율, 호수밀도
 ├─ 3. 요건판정      별표 1 + 인천 조례 항목별 ○/× 와 부족분("노후 건축물 7동 더 필요" 등)
 ├─ 4. 토지이용계획  획지·도로·공원·학교·공공공지 면적 배분 → 토지이용계획표 자동
 ├─ 5. 밀도계획      기준→허용→상한 용적률, 공공기여·국민주택규모 주택, 개략 세대수
 ├─ 6. 도서 초안     4장 목차대로 문서 생성(HWPX/DOCX 내보내기는 2단계)
 └─ 7. 검토 모드     제출 수치 입력 → 공부 대조 → 오류 목록
```

### 6. 시험 사례: 용현1구역

- 면적 약 15만㎡, 경사지, 학교예정부지 필요, 중심부 문화재 이전 필요
- 두 추진주체(A안·B안)의 구역계가 서로 다름 → **구역계 비교 기능**(같은 기준으로 A·B안 요건 판정을 나란히 표시)을 1단계에 넣습니다.
- 시험용 데이터는 지번·건축물 공부만 쓰고, 소유자 정보는 `_비공개` 폴더에만 둡니다.

### 7. 단계

| 단계 | 내용 |
|---|---|
| 1단계 | 구역계 입력, 지적·건축물대장 자동 수집, 현황분석, 요건판정, A·B안 비교, 시제품 수준의 정비계획·개략 건축계획·사업성 |
| 2단계 | 인센티브 배점·공공기여 산식, 초안 도서 화면 출력, 상가·보상비 반영 |
| 3단계 | 검토 모드, HWPX/DOCX 내보내기, `/arch`(개략 배치)와 데이터 연동 |

## 2부. Claude Code 지시문 (아래를 그대로 붙여 넣으세요)

```
저장소 redev-feasibility에 jbslab.co.kr/urban 경로로 "정비구역 지정 및 정비계획 초안" 기능을 추가한다.
이번 작업은 1단계만 한다. 작업 중 질문하지 말고 끝까지 진행한 뒤 결과를 한글로 보고해라.

[기준 디자인]
- 내가 함께 주는 urban-prototype.html을 docs/urban-prototype.html로 저장소에 넣고, /urban 화면은 이 시제품을 기준으로 만든다.
- 그대로 따를 것: 상단 단계 탭(구역계·현황 → 요건판정 → 정비계획 → 개략 건축계획 → 사업성, 적용 기준), 좌측 도면 + 우측 수치 패널 배치, 구역계 적색 일점쇄선(stroke-dasharray "7 2 1.2 2"), 도면 색 구분(노후·불량/과소필지/접도/용도지역/개략 배치), 판정 문구("기준 대비 ○동 부족"), 안별 비교표, jbslab 마크.
- 계산 함수(obsoleteRule, densityUnits, analyze, judge, plan, biz)는 시제품 코드를 옮기되 기준 수치는 시제품 안의 RULES 대신 rules/incheon.json에서 읽는다.
- 시제품의 예시 구역 생성부(roads·parcels·buildings를 rng로 만드는 부분)만 실제 데이터 수집으로 바꾼다. 실제 데이터가 없을 때는 시제품 예시 구역을 "예시 데이터" 표시와 함께 보여 준다.
- 정비계획·개략 건축계획·사업성 탭은 시제품 수준(가정값 입력 + 개략 계산)으로 이번에 함께 옮긴다. 가정값에는 "예시 가정" 표시를 유지한다.

[원칙]
- 기존 jbslab 본체의 라우팅·로그인·공통 레이아웃·지도 컴포넌트를 재사용한다. 하위 도메인이 아니라 같은 도메인의 /urban 경로다.
- 개인정보(소유자 이름·주소·연락처·동의서)는 저장소에 커밋하지 않는다. _비공개 폴더는 .gitignore에 있는지 확인하고 없으면 추가한다.
- V-World·공공데이터포털 API 키는 코드에 쓰지 않는다. 기존 jbslab의 키 관리 방식을 따르고, 없으면 환경변수(.env, 커밋 금지)로 둔다.
- 법정 기준 수치는 코드에 하드코딩하지 않는다. rules/national.json(시행령 별표 1)과 rules/incheon.json(인천 조례·기본계획)으로 분리한다.
  rules/incheon.json은 내가 함께 주는 파일을 그대로 넣는다. 값을 바꾸지 마라.
  각 항목의 status가 "press"인 값은 화면에 "고시문 대조 필요" 표시를 붙이고, 없는 값은 "기준값 미입력"으로 표시한다. 임의 값을 넣지 마라.
  과소필지는 분할제한면적 "미만"(주거지역 60㎡)이다. 90㎡로 쓰지 마라.

[1단계 기능]
1. 구역계 입력
   - 지도에서 폴리곤 그리기, GeoJSON/SHP(zip) 불러오기, 저장·불러오기(브라우저 로컬)
   - 구역계를 여러 개(A안·B안 등) 만들어 나란히 비교하는 화면
   - 구역 면적(㎡) 자동 계산

2. 현황 자동 수집
   - 구역계와 교차하는 연속지적 필지 추출: 지번, 지목, 공부면적, 편입면적, 편입비율
   - 각 필지의 건축물대장 표제부 조회: 사용승인일, 주구조, 지상층수, 연면적, 주용도, 세대수
   - 토지이용계획: 용도지역별 면적
   - 무허가건축물은 수동 입력 표(위치·구조·추정 건축연도·면적)를 둔다.
   - 결과는 표와 지도 양쪽에 보여 주고 CSV로 내려받게 한다.

3. 현황분석 계산
   - 노후·불량건축물 판정: 시행령 제2조 + rules의 준공 경과연수 기준(구조·용도·준공연도별). 판정 근거(어느 기준으로 노후인지)를 건축물마다 표시
   - 노후도(동수 기준), 노후도(연면적 기준) — 무허가건축물 포함/제외 두 값 모두
   - 과소필지 비율, 주택접도율(도로 폭 기준값은 rules에서 읽음), 호수밀도(동/ha; 공동주택·다가구는 rules의 산정 방식 적용)
   - 모든 계산값 옆에 "산식"과 "분자/분모"를 함께 보여 준다(검토 모드에서 그대로 쓸 예정).

4. 요건판정
   - 사업 유형 선택: 재개발 / 재건축 / 주거환경개선
   - 시행령 별표 1의 항목별 충족 여부(○/×)와 근거 수치, 미달 시 부족분을 문장으로 출력
```
