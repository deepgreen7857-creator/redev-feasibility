# 사업성 화면 ↔ /arch 1차·2차 건축계획 연동 지시문 (노트북 Claude Code용)

## 배경 (업무 흐름)
구역 설정(/urban) → **1차 개략 건축계획(/arch)** → **초기 사업성** → 교통성·환경성 검토(/traffic, /env)
→ **2차 건축계획(/arch, 검토 결과 반영)** → **사업성 다시 보기** → 높이·경관(/landscape)

/arch는 이미 바꿔 놓았다.
- 확정할 때 단계별로 저장: `site.arch.stages[1]`(1차, 초기 사업성용), `site.arch.stages[2]`(2차, 검토 반영)
- `site.arch.chosen`은 항상 마지막으로 확정한 안이고 `chosen.stage`(1|2), `chosen.stageName`이 붙음
- `chosen.ex` = { legal 법정 주차, plan 계획 주차, ugArea 지하주차장 연면적㎡, ugFloors 지하 층수, comm 주민공동시설㎡, mgmt 관리사무소㎡, totalGfa 총 연면적 추정㎡ }
- 확정 뒤 버튼이 `../?arch=<site id>`로 사업성 화면을 연다

## 할 일 (js/assume.js 등 사업성 화면)
1. 주소에 `?arch=<id>`가 있으면 그 구역의 확정안을 '세대수 기준'으로 바로 골라 비례율까지 계산해 보여준다(사용자가 다시 고를 필요 없게).
2. 고른 안 옆에 단계 표시: "1차 개략(초기 사업성)" / "2차(교통·환경 반영)". `stages`에 1·2가 모두 있으면 둘 중 고를 수 있게 하고, 기본은 2차.
3. 1·2차가 모두 있으면 비례율·총수입·총사업비를 나란히 보여주는 비교 줄(또는 표)을 단다.
4. 공사비 산정에 연면적을 쓰는 곳이 있으면 `chosen.ex.totalGfa`(지상+지하주차장+주민공동시설+관리사무소)를 '개략 건축계획 기준'으로 고를 수 있게 한다. 값이 없으면 기존 방식 그대로.
5. 예전에 저장된 안(`stage`·`ex` 없음)은 1차로 보고 그대로 동작.

## 손대지 말 것
- /arch, /traffic, /env, /landscape, shared/ 파일
- shared/criteria/*.json 법령 숫자

## 확인
- /arch에서 1차 확정 → [초기 사업성 보기] → 세대수 기준이 자동 선택되는지
- 교통·환경 검토 후 /arch 2차 확정 → [사업성 다시 보기] → 2차가 기본, 1차와 비교되는지
